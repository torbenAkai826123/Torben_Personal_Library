# 請求收件匣

將待處理請求寫成獨立的 Markdown 檔案，放在此目錄，例如 `2026-09-30-adjust-tool-window.md`。此目錄是提交入口；放入檔案不會自動觸發執行。請在對話中指定要處理的檔案或提出明確請求。

每份請求請包含：

- **目標**：期望使用者能觀察到的結果。
- **完成判準**：可以用操作、測試或檔案檢查驗證的條件。
- **範圍與限制**：允許及禁止變更的內容；若無特別限制，可註明由執行者依 `AGENTS.md` 判斷。
- **背景或建議做法**（選填）：相關檔案、現象、參考資料與偏好的實作方向。

若目標或判準無法驗證，處理前需先釐清。已授權目標內可解決的技術阻礙由執行者處理並回報；只有重大取捨或超出授權範圍才需再次決定。請參考 [Goal driven 範例](../goal-driven-example.md)。

讀取後原請求的處理：

- 開始處理時，將請求檔移到 `docs/inbox/processing/`，檔名不變。`processing/` 只放進行中或暫停的請求。
- 完成判準全部驗證通過後，將請求檔移到 `docs/inbox/archive/<完成當日日期>/`，日期格式為 `YYYY-MM-DD`，檔名不變。
- 封存屬於該請求的變更範圍：使用者要求 commit 時，與該請求的成果放在同一個 commit。
- 未完成時，在檔名後加上 `-事由`，例如 `計算機移出 Core-作廢.md`：
  - 被阻擋或只完成部分判準：留在 `processing/`，在回報中說明原因。由使用者決定之後是否繼續；使用者表示不再執行時，才移到 `archive/<日期>/`。
  - 使用者明確表示作廢：移到 `archive/<日期>/`。
- 不修改請求檔內容。需要記錄問題原因時，先取得使用者同意再寫入。
